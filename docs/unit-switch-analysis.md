## 2. Bug ที่เจอเพิ่ม: สลับไปกลับแล้วน้ำหนักเพี้ยน

`setUnit()` (`build.py:858-867`) แปลงค่าในช่อง input ทุกครั้งที่สลับ และปัดเศษเป็น 0.5 ทุกรอบ
ค่าจึงเพี้ยนสะสม:

```
25 lbs  → 11.5 kg → 25.5 lbs   (เพิ่ม 0.5)
40 lbs  → 18 kg   → 39.5 lbs   (หาย 0.5)
15 lbs  → 7 kg    → 15.5 lbs
12.5 lbs→ 5.5 kg  → 12 lbs
```

ถ้ากดสลับบ่อยขึ้นเพราะปุ่มอยู่ใกล้มือ (ซึ่งคือเป้าหมายของงานนี้) bug นี้จะโผล่บ่อยขึ้น
และน้ำหนักผิดจะถูกบันทึกลง log จึงควรแก้พร้อมกัน

## 4. แผนแก้ (ข้อ A + bug)

1. **`build_template_section`** (`build.py:278-279`) และแถวใหม่จาก `addrow` (`build.py:829-830`)
   - เปลี่ยน `<span class='w-unit'>` เป็น `<button type='button' class='w-unit' title='Switch lbs/kg'>`
   - เก็บค่า lbs ดั้งเดิมไว้บน input: `<input … class='w-num' data-lbs='{num}'>`

2. **กดป้ายแล้วสลับหน่วย** ใน `SAVE_SCRIPT` ใช้ event delegation อันเดียว รองรับแถวที่เพิ่มทีหลังด้วย:
   ```js
   document.addEventListener('click', e => {
     const b = e.target.closest('.w-unit');
     if (b) setUnit(UNIT_SEL === 'kg' ? 'lbs' : 'kg');
   });
   ```

3. **แก้ค่าเพี้ยน** ใน `setUnit()` ให้แปลงจากค่า lbs ต้นฉบับ (`data-lbs`) ไม่ใช่จากค่าที่ปัดเศษไปแล้ว
   - ตอนผู้ใช้พิมพ์ (`input` event) ให้อัปเดต `data-lbs = inLbs(value)` ใหม่
   - ตอนสลับ: `i.value = fromLbs(parseFloat(i.dataset.lbs))` (ปัดเศษแค่ตอนแสดงผล)
   - `rowData()` อ่าน `data-lbs` ได้เลย ไม่ต้องแปลงซ้ำ
   - ผล: 25 lbs → 11.5 kg → **25 lbs** (กลับมาเท่าเดิม)

4. **ไม่ให้หน้าจอกระตุก:** ความกว้างช่องไม่เปลี่ยนตอนสลับ (`lbs`/`kg` ต่างกัน 1 ตัวอักษร)
   จึงไม่ต้องทำอะไรกับ scroll position ถ้าเห็นว่าขยับ ค่อยใส่ `min-width` ให้ `.w-unit`

5. **CSS** (`build.py:1199`): ใส่ `cursor:pointer` และสถานะ `:hover`/`:active` ให้ `.w-unit`
   ให้ดูออกว่ากดได้

6. **อัปเดตเอกสาร**
   - คอมเมนต์ที่ `build.py:305-314` ล้าสมัยแล้ว (ยังเขียนว่า "the UI has no unit switch" และ "shows BOTH lbs and kg")
   - `AGENTS.md:34-39` เพิ่มว่าป้ายหน่วยในแต่ละแถวเป็นปุ่มสลับของสวิตช์ตัวเดียวกัน
